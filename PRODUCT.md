# Product

<!-- impeccable:product-schema 1 -->

## Platform
web

## Product Purpose
JD Krasnick's personal portfolio and technical blog. Visitors can explore his work and read articles. JD can write, preview, and publish technical posts.

## Operating Context
Astro website with public article reading, a password-protected hosted owner editor, and a localhost authoring workflow. Hosted drafts and pictures use private Vercel Blob storage; GitHub preparation and publication remain local.

## Capabilities and Constraints
The blog is independent of the portfolio homepage and reachable from the header on the hero screen. The approved hero and portfolio refinements remain intact. Hosted authoring and previews require a server-verified owner session, stay absent from public navigation and indexing, and never enter public caches. Private Vercel Blob storage holds hosted drafts and pictures. Saving never publishes a post. Preparing a post writes reviewed Markdown under content/blog; publishing is a Git commit and push. Each post may have an optional picture and alternative text, validated and preserved as image/imageAlt Markdown frontmatter. Add picture discloses a cover dropzone and file picker, an optional HTTPS or root-relative picture URL, alternative text, live preview, load-error feedback, and removal. Insert picture opens a body file picker; file drops and clipboard pictures insert into the body in both Write and Markdown modes at the drop position or current selection.

The localhost POST /api/blog/upload endpoint validates decoded PNG, JPG, WebP, GIF, and AVIF data up to 10 MB and 40 megapixels, including animation frames. It preserves original files under public/blog-images/uploads with a sanitized filename stem and content hash, returning a relative URL for the post. Commit image assets with the prepared Markdown; remote URLs remain externally hosted. Draft text stays private, but files under public are public in any deployment that includes them, even when the draft has not been prepared. Removing a picture or deleting a draft keeps its asset so shared references continue to work. Visitors can comment directly on articles anonymously, without an account. Comments require rate limiting and abuse defenses. Local comments persist in files; the hosted Vercel comment API uses server-only Redis REST credentials, which still need configuring before deployment.

Hosted picture uploads accept the same formats up to 4 MB and remain private behind authenticated image URLs. Concurrent saves use revisions and conditional writes to protect against stale tabs. Hosted authoring does not prepare or publish GitHub files.

Posts support small animations and interactives through fenced demo JSON referencing standalone HTML/CSS/JavaScript under public/blog-demos. Machine editability takes priority: Markdown, JSON configuration, and plain static files require no demo framework or build step. Insert demo keeps configuration directly editable in Write or Markdown; Preview runs the embed. Reader embeds use scripts-only sandboxed iframes without same-origin access; raw article scripts and iframes remain sanitized. Preparation/build reject invalid configuration or missing referenced files. Demo assets are public when deployed and must be committed with the prepared post; article drafts remain in their separate local or authenticated hosted storage. The detailed author/agent workflow is docs/blog-authoring.md.

The hosted and localhost editors share Paragraph/H2–H4, bold, italic, strike, inline/fenced code, links, quotes, bullet/numbered lists, dividers, tables with row/column insertion and deletion, and undo/redo. Write adds clear formatting and list indent/outdent. Literal find/replace in Write and Markdown provides Match case, Previous/Next, Replace and Replace all while preserving the rest of the document. The inline shortcut guide, mode/source-formatting shortcuts, and visible save status support keyboard editing. Undo history resets per loaded draft; failed or timed-out saves keep browser recovery text. Preview saves first and displays the sanitized article and running demos in the same window. The stable Preview toggle exposes its pressed state; Cmd/Ctrl+Shift+P toggles it, and Escape or Edit post returns to the prior field, selection and scroll. Hosted editing and preview require the owner session.

The optional assistant differs by environment. On localhost it uses the installed Codex CLI and ChatGPT subscription for read-only ephemeral writing sessions; API-key accounts are rejected before inference, credentials stay with Codex, and shell, external MCP integrations, plugins and image-generation tools are disabled. Stop, New chat, Reconnect, browser history and job IDs support response recovery; the local bridge permits one running response and retains at most 20 jobs in memory. Hosted authoring instead copies the request and opens ChatGPT in a separate window; it makes no local-chat API requests and stores no ChatGPT credentials on the server. Post attachment starts unchecked in both workflows; explicit attachment or Use selection includes only author-chosen context. Local replies support Copy reply and fenced-block Copy code, and disable embedded media to prevent automatic media fetches. Image requests prefer reproducible Python/Pillow scripts that save a PNG. Create image script seeds an empty composer without sending or overwriting text; the author copies and runs code, then drops the PNG into the post. External ChatGPT image generation remains optional. No billed Images API is called, and the helper does not execute code, edit the post or publish it.

Prepared Markdown posts build to `/blog/<slug>/` with full sanitized article HTML, article metadata and BlogPosting structured data. The blog index includes readable HTML and direct article links; JavaScript adds search, comments and demos but is not required for reading. Legacy query-based article URLs redirect permanently to the static article path. The generated sitemap includes only the homepage, blog index and prepared posts; robots allows public crawling while excluding private authoring routes. Owner-session checks still protect hosted editor, draft, preview and API access; login and private authoring responses retain their private headers. Article descriptions vary by post while the Layout Person/WebSite biography stays constant.

## Brand Commitments
Preserve the site's dark blue identity, as explicitly requested. Follow the user's Dan Luu reference for a simple, readable blog with minimal clutter: date/title links and comfortable page width. Pictures are optional but prominent, leading on the left beside each article's date and title. Do not display post icons in the index or editor; older icon metadata remains supported for compatibility. The editor should feel like the actual article, directly editable, without split panes or a confined writing window. Preserve existing portfolio content and navigation.

The blog supports user-selected Porcelain light mode and Soft navy dark mode; the portfolio retains its existing dark identity. Appearance defaults to the system theme, with explicit light/dark overrides saved only in the current browser. Reading font options are Source Sans 3 (default), Lato, IBM Plex Sans, Literata, and the original Inter. Literata uses Source Sans 3 headings; other fonts apply to article headings and prose. The reader, visual editor, and preview share these preferences without changing post content or publication state. Prose uses 21px desktop/20px mobile and 1.75 line height in a shared 680px document column on desktop. Code and Markdown source remain monospaced. Paragraphs, lists, blockquotes, code, tables, pictures, and demos share the document's left/right edges.

The user selected the Roomy & familiar article header: larger Inter titles, a distinct subtitle from the post excerpt, and generous space before the cover picture. Reader and editor share the approved title/subtitle scales. Omit the author byline from the reader, editor, and local typography previews; keep the site's name in navigation and footer. The reader retains its date and example label, and the editor retains its state badge. This header refinement preserves body prose and does not prepare or publish private drafts.

Search and topic filters open from a magnifying-glass icon into a nonmodal side panel. Engineering and Research remain available alongside existing post tags. Closing the panel preserves filters; clear explicitly resets them. The control identifies active filters and supports keyboard focus and Escape dismissal.
